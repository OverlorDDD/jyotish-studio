# Panchanga 2.0 — P2.2 Live Vedic Day (2026-11-02)

## Goal and source of truth
P2.2 builds on the P2.1 verified Swiss/Lahiri/Delta-T five-anga calendar. The same /day response now exposes **full named periods**, not just anonymous numeric transition indexes. It does NOT alter JQA-3 natal mathematics, saved charts, OAuth/session data, selected natal place, SEO metadata, R4.3 IndexNow, GA4, news, eclipses or the approved #6 brand.

## Canonical day semantics and correctness
- Each observer-local Vedic day spans `[sunriseUtc, nextSunriseUtc)`; midnight is not the day boundary. Durations may be ~23/25h on DST changes.
- For tithi, nakshatra, nitya yoga and karana, the pure core function `buildPanchangaSunrise` returns `periods[kind][] = {index,startUtc,endUtc,value}`. Every start/end is obtained from the existing ephemeris crossing solver. `value` is sampled at the exact change plus 2 seconds using the **same** Sun/Moon adapter as the sunrise state and verified to match `nextIndex`. The final end may extend beyond the next sunrise and must never be clipped in the text.
- Vāra is the weekday **at local sunrise** and remains unchanged until the next sunrise. Its range is `[sunriseUtc,nextSunriseUtc)`.
- The daily response retains `version:panchanga-five-anga-v1`, `sunrise`, `boundaries`, `changes`, `astronomicalEvents`, kalas, source and methodology (additive contract).
- Web presentation `slicesFor` clips visual bars to the chosen sunrise window **only**; exact period start/end texts show un-clipped times and dates. Invalid, discontinuous or unverified periods are rejected instead of being interpolated.
- Live panel shows "now" only if client time lies within a verified sunrise day. If the selected local civil date is before sunrise, client loads **previous** sunrise day's /day data. If that read fails, live status is explicitly unavailable; the coming sunrise is never mislabeled as current.
- For historical/future dates, cards say "At sunrise", not "Right now"; user clock is refreshed every 30 seconds with automatic interval cleanup. The device clock is identified as the source of "now".
- All UTC instants are formatted through Intl in selected observer IANA time zone, with **day and month** at every start/end or transition, so after-midnight instants cannot be confused with previous date.
- Each transition shows a localized name (not '#12'), including actual future period. Four horizontal lanes + text-based chronological list. The list stays keyboard-accessible and doesn't depend on color alone; reduced-motion respected.
