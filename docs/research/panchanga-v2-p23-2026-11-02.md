# Panchanga 2.0 — P2.3 Smart Week / Month (2026-11-02)

## Scope & UX
The public Panchanga has one combined, location-aware Vedic week/month overview. Seven-day cards show five sunrise limbs, lunar-month names and chronological festival/phase markers. Month grid (28–31 days) provides previous/next month, bilingual names, Amanta/Purnimanta choice, and All/Festivals/Phases filters; selecting a day opens the P2.2 exact local-sunrise timeline. No extra tabs are added to the site header.

Astronomy and traditional calendar decisions are kept distinct: new/full/quarter Moon marks are numerically isolated geocentric Sun–Moon elongation crossings, **not eclipses**; observances are explicitly labeled candidates, **not certified regional fasting or Parana dates**. All five limbs and lunar months represent the instant of local sunrise, not the current moment.

## Technical architecture and resolved blockers
- New `GET /api/v1/vedic-calendar/overview?start=YYYY-MM-DD&days=1..31&zone=<IANA>&latitude=<number>&longitude=<number>&monthSystem=amanta|purnimanta`.
- Uses the existing **single Swiss verified batch rise/set worker** plus `createVerifiedSiderealPlanetAt()` for all five anga values, lunar months, named observance candidates, Sankranti and exact phase events; no 31 per-day HTTP requests, no fallback astronomy, and no LLM.
- The original `/api/v1/vedic-calendar/week` continues to accept **only 1–7 days**. New `sunriseAngas` and `phaseEvents` fields are additive to its response. `/api/v1/panchanga/day` and `/range` remain unchanged.
- Because `solarSankrantis` explicitly refuses search windows beyond 15 days, a 31-day month uses contiguous, non-overlapping half-open 14-day chunks. Events exactly at midnight have one owner, no duplications.
- Full/new/quarter Moon uses 2h state brackets and <=1s bisection. Civil date association uses the observer's true IANA timezone, including DST. Phase geometry is not independent reference certification.
- Worker concurrency: two Swiss child processes; up to six FIFO waiters, 15s wait deadline, per-worker timeout bounded by 16s+650ms/day (max45s). Queue overload/errors fail closed, not fabricate data. Completed requests share five-minute in-flight cache keyed by date, coordinates, zone and month system.
- Range view mounts **only overview**; historical supplementary astronomy/festival panels stay available in **day view**. Day API requests are skipped in week/month, avoiding redundant worker requests and 503 bursts on small AWS.
- Mobile grid supports 320px and reduced motion; text labels, keyboard buttons and non-color-only categories remain accessible.
