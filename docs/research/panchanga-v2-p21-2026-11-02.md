## User-facing hierarchy
The public `/uk/panchanga` and `/en/panchanga` pages retain their canonical URLs, SEO descriptions and existing long-form search guide. They now lead with day/7-day/month choice and five sunrise limbs, followed by supplementary astronomy, personalized lunar strength, candidate festivals, eclipses and source provenance. Date and city are prominent; explicit coordinates/IANA timezone are behind an advanced details control. Manual city selection requires **Calculate day** to apply and save.

This release's week/month grids show **five angas at each local sunrise**, not every within-day transition: selecting a grid day shows the existing exact-boundary day report. P2.2 should add a unified sunrise→next-sunrise transition timeline, named next anga instead of numerical index, and a live-current instant; no UI claim here that sunrise-state equals live-now.

## Saved location priority, boundaries and privacy
Authenticated `GET /api/v1/personal/panchanga/location` returns, in order:
1. Explicit saved Panchanga observer (`panchangaPlace`, `panchangaTimeZone`, latitude, longitude)
2. Selected natal chart owned by the user (`primaryChartId`)
3. Most recent saved chart owned by the user if no primary is selected
4. `source:none` if no valid chart location exists (UI defaults to Kyiv)

`PUT` validates name, finite coordinates and a real IANA zone, requires an authenticated session and same-origin request. It upserts **only** the nullable Panchanga preference fields. `DELETE` clears those fields, reverting to the owned chart or default. Natal birth place/time/date are never altered. Personal horoscope timezone is not changed. `Cache-Control: private, no-store` for all preference endpoints; no preference is included in growth analytics events. **Note:** the existing public read-only astronomy GET endpoints still receive observer coordinates in request query parameters, as before. Do not promise secrecy from proxy/access logs. A future privacy-focused follow-up can move client calculation requests to POST bodies and update logging.

The profile save checkbox is on by default for signed-in users. A place chosen on the form is persisted on Calculate; deselecting the checkbox runs a one-off calculation. Guests never write preferences.

## New range contract
`GET /api/v1/panchanga/range?start=2026-11-01&days=30&zone=Europe%2FKyiv&latitude=50.4501&longitude=30.5234`

- Input: exact Gregorian date in 1900–2099, valid IANA time zone and observer coords, integer `days` 1–31. Bad input 400; missing Swiss sunrise/planet source 503 and no speculative records.
- Output: `panchanga-range-v1`, observer metadata, astronomy source/profile, and ordered civil days. Every item has local sunrise UTC, sunset UTC, next sunrise UTC, and five limbs **at sunrise** from the existing pure `fiveAngas` engine; no fabricated within-day boundaries.
- One bounded `riseSetBatch` async worker covers 1–31 days. Festival endpoint's separate validation remains limited to 1–7 days. Python max increased to 31; output guards increased to 40 rise/set events. Existing two-concurrent-worker limit remains.
- Bounded 5-minute in-flight memoization for repeated public requests (8 entries), including fast rejection removal. CPU ephemeris positions use the existing verified Swiss/Lahiri/Delta-T adapter; no network calendar API or AI.
- This is a **structural solution to the original no-month-API blocker**, but must be validated under production load before claiming operational closure.

## Manual verification
- Unauthenticated: UK/EN daily five limbs immediately after the chooser; seven-day and current-month views work for Kyiv. Open month day → daily calculations return. Search global city and submit.
- Authenticated without chart: Kyiv default; select another city, Calculate, reload and confirm saved city. Uncheck save, select another city, Calculate and reload: previous saved city should remain.
- Authenticated with one chart or selected primary: clean preference → derives that chart's **location** but not its birth date. Change to another city → Calculate → reload restores saved city. Restore natal location → selected chart's city returns. Check saved chart JSON and Personal horoscope time zone remain identical.
- Verify Kyiv/New Delhi/London dates, DST change dates, month lengths 28/29/30/31, strict 32-day rejection, 503 when Swiss unavailable, blocked anonymous preference endpoint, mobile 320/360/390/430px and desktop.
- Compare `/day` and `/range` sunrise fiveAngas for identical observer/date. Never equate one-second mathematical root isolation with independent astronomical accuracy certification.
