# Galaxiora — повний запуск на Windows та перевірка всіх модулів

Оновлено: 18.10.2026. Репозиторій GitHub лишається `OverlorDDD/jyotish-studio`, але публічний бренд — **Galaxiora**.

## Передумови

- Windows PowerShell, Node.js 24, npm, Git та Docker Desktop (Linux Engine).
- Папка: `C:\Users\Note\jyotish-studio-git`.
- За замовчуванням Next.js — `http://localhost:3000`, NestJS — `http://localhost:4000`, PostgreSQL через Docker — `127.0.0.1:5433`.
- Зупинити попередні `npm run dev` / `npm run dev:full`, що займають ті ж порти. OpsPilot не запускайте одночасно на тих самих портах.
- Не видаляйте том БД. **Ніколи не використовуйте `docker compose down -v` для звичайного перезапуску.**

## Крок 1. Отримати найновіший код

```powershell
cd C:\Users\Note\jyotish-studio-git
git status --short
git pull --ff-only origin main
git log -1 --oneline
npm run | Select-String "admin:setup|test:brand"
npm install
```

Якщо `git pull` заблокований через локальні незбережені зміни, збережіть їх перед повторною спробою. Не видаляйте бездумно `apps/web/next-env.d.ts` і `package-lock.json` — раніше саме ці файли відображалися як змінені.

`Missing script: admin:setup` означає старий `package.json`. Перевірте, що `git pull` дійсно завершився і `npm run` бачить `admin:setup`. У попередньому логу Git успішно підтягнув етап 3 (`4499e66`), але не етап 4 (`cdf7f403`) із командою створення адміністратора.

## Крок 2. Запустити БД

Запустіть **Docker Desktop** звичайним способом у Windows; дочекайтеся **Engine running**.

```powershell
docker info
docker compose up -d db
docker compose ps
npm run db:doctor
```

У `docker compose ps` потрібен контейнер `jyotish-db` зі станом running/healthy. Якщо Docker не працює, Prisma згодом видасть `P1001 localhost:5433`.

## Крок 3. Перевірити локальне оточення і БД

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run db:generate
npm run db:migrate
```

`DATABASE_URL` у локальному `.env` має відповідати запущеному Docker PostgreSQL на `localhost:5433`. Не перезаписуйте існуючий `.env` і не публікуйте `AUTH_SECRET` чи API-ключі.

Якщо `AUTH_SECRET` відсутній, задайте у `.env` власний 32+ символьний секрет, згенерований командою:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Секрет потрібен для реєстрації та сесій. Не замінюйте без причини чинний секрет: старі сесії можуть перестати перевірятися.

## Крок 4. Перевірити код

```powershell
npm run test:all
npm run test:swagger
npm run build
```

Ці перевірки не вимагають відкритого браузера. Якщо збірка неуспішна, не переходьте до публічного запуску.

## Крок 5. Створити першого ADMIN

Для **вже зареєстрованого** акаунта за умови відсутності інших адміністраторів:

```powershell
npm run admin:setup
```

Інтерактивна команда покаже зареєстровані email у локальній БД. Виберіть **свій** акаунт та введіть точний рядок `PROMOTE <email>` на вимогу програми. Якщо адмін уже є, цей сценарій навмисно не працює; існуючий адмін видає ролі через `/uk/admin`.

Якщо акаунт ще не зареєстровано, спершу запустіть сайт, зареєструйтеся, після чого з іншого терміналу виконайте `npm run admin:setup`.

## Крок 6. Запустити всю платформу

```powershell
npm run dev:full
```

Не закривайте це вікно PowerShell — воно підтримує обидва процеси:

- сайт: `http://localhost:3000/uk` (або `/en`);
- backend: `http://localhost:4000/api/health` (очікується `status: ok` і `database: connected`);
- Swagger: `http://localhost:4000/api/docs`.

Для зупинки натисніть **Ctrl+C** у вікні із серверами. Для наступного запуску в новий день достатньо: Docker Desktop → `docker compose up -d db` → `npm run dev:full`. Повторювати міграції чи npm install щодня не потрібно, лише після оновлення коду.

### Обов'язкові негативні перевірки доступу

1. Без входу відкрити `/uk/admin`: backend повинен відмовити в адміністративних даних.
2. В іншому акаунті `MEMBER` адміністративний API повинен повертати 403, а чужі чернетки й карти — не бути доступними.
3. Через адмінпанель видати тестовому акаунту `EXPERT`, перевірити журнал, потім повернути `MEMBER`. Не тестувати зміну на власному адмінському акаунті.
4. Четвертий розклад Таро за UTC-добу не повинен проходити; оновлення сторінки не повинно відновлювати ліміт.
5. Незаповнена згода на зберігання запитання не повинна дозволяти відправлення; після збереження має з'явитися модальне вікно з неактивною оплатою.

## A5 — додаткові ручні перевірки, починаючи з Docker

1. Запустіть **Docker Desktop** → дочекайтесь статусу `Engine running`; відкрийте PowerShell в `C:\\Users\\Note\\jyotish-studio-git`.
2. Зупиніть старий `npm run dev:full` клавішами `Ctrl+C`; Docker при цьому не видаляйте.
3. `docker compose up -d db` → `docker compose ps`: контейнер `jyotish-db` має бути running/healthy; порт host 5433.
4. `git status --short` → `git pull --ff-only origin main` → `npm install`. Якщо локальні зміни блокують pull, спочатку збережіть їх; не використовуйте `reset --hard`.
5. `npm run db:generate` → `npm run db:migrate` → `npm run security:check`; жодних видалень БД.
6. `npm run test:content:a5` → `npm run test:all` → `npm run test:swagger` → `npm run build`.
7. `npm run dev:full`, відкрийте `http://localhost:3000/uk/yoga` і `http://localhost:3000/uk/learn` та пройдіть перевірки нижче.

**Yoga:** усі 4 картки ведуть до різних практик; інструкції й альтернативи мають реальний зміст; таймер зупиняється кнопкою Пауза; перемикач «Без таймера» залишає вільне проходження; Назад/Далі/Завершити/Повторити не перекидають автоматично та не потребують реєстрації. На сторінці практики перемкніть EN/UA — slug має зберегтись.

**Academy:** у каталозі 3 теми та 7 різних уроків; урок має 3 текстові розділи, 3 висновки, тест із трьома відповідями; перевірте помилкову відповідь, «Повторити» і правильну відповідь; переходи до Jyotish, Tarot або Yoga; мовний перемикач зберігає slug.

**Регресія:** карти Jyotish D1/D9/D10, Tarot v2 на 1/3/10 карт, приватна історія, ADMIN/MEMBER права. На мобільній ширині 360 px не повинно бути горизонтального скролу. В браузері F12 → Console — без нових помилок.

**SEO:** на localhost залишайте `SITE_NOINDEX=1`. Не намагайтесь активувати індексацію, доки немає власного стабільного HTTPS-домену. В CI окремо перевіряються всі `/uk` та `/en` посилання, sitemap та hreflang.

## Що ще не готове

Справжні платежі, повернення коштів, персональні відеокабінети виконавців, прикріплення й приватна доставка відео, повноцінна бібліотека практик, західна астрологія, публічний домен та мобільний застосунок ще потребують реалізації.

Юридичну перевірку Galaxiora (домени та торговельна марка) і комерційну ліцензію Swiss Ephemeris потрібно провести до платного публічного запуску.

## Локальні помилки

- `PSReadLine ArgumentOutOfRangeException` на Ctrl+V: це проблема виводу PowerShell. Перезапустіть Windows Terminal, збільшіть його висоту, вставляйте короткі команди по черзі.
- `P1001 localhost:5433`: Docker Desktop/PostgreSQL недоступний; перевірте `docker info` і `docker compose ps`.
- `Missing script: admin:setup`: не оновився `package.json`; перевірте `git pull --ff-only origin main` і `npm run`.
- `npm audit` може показати вразливості в залежностях. Зафіксуйте `npm audit --omit=dev` для аналізу, але не запускайте `npm audit fix --force` без окремої перевірки сумісності.
