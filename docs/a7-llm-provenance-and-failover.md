# A7.1 — live LLM verification and failover (2026-10-20)

## What the reader actually displays

The main eight-part consultation is produced deterministically from validated classical chart facts. It is **not** LLM-generated. The optional additional section must be generated by an accepted external model response and is tagged `source: 'llm'`, including provider, model and response replay-cache status. A failed/no-key/disabled model is tagged `source: 'deterministic'` and displays the sanitized fallback reason in a visible status message. A loading spinner or lengthy calculation is **never** evidence of actual inference.

`POST /api/v1/reports` uses independently validated D1/D9/D10 rules, ranked v3 finding IDs and verified chart evidence. The language model synthesizes traditional significance rather than fabricating chart positions. A free response is accepted only after schema/ID/repetition verification. The original numeric chart comes solely from Swiss Ephemeris and the rule engine. Existing historical snapshots remain unchanged.

## Providers, failover and zero-cost safety

1. **OpenRouter `openrouter/free`** — dynamic router selecting amongst currently available *free* underlying models. No paid model is passed through this path. One schema retry is allowed after format failure.
2. **Google Gemini** — an **independent** remote API endpoint, `generativelanguage.googleapis.com/v1beta/openai/chat/completions`, pinned to `gemini-2.5-flash-lite`. This provider is disabled until BOTH `GEMINI_API_KEY` and `GEMINI_FREE_TIER_CONFIRMED=1` are configured. Before enabling, verify that the account's **billing is off**, that this model is available on your free tier, and that your account's free limits suffice. Changing to a billed tier can incur charges; disable this toggle immediately if billing changes. See [Google's pricing](https://ai.google.dev/gemini-api/docs/pricing) and [OpenAI-compatible endpoint](https://ai.google.dev/gemini-api/docs/openai).
3. **Ollama** — local model; `OLLAMA_ENABLED=1` and `ollama pull gemma3:1b`; no external API charges, but uses your computer resources.

Default `FREE_AI_ORDER=openrouter,gemini,ollama`. Disabled/missing-key providers are skipped. Failures, rate limits and invalid prose attempt the next configured provider. Every remote cloud request counts towards `FREE_AI_MAX_CALLS_PER_HOUR`; no free-mode fallback calls paid OpenAI. Do not add alternative routes that quietly use paid model IDs. Multiple providers do not imply an SLA or eliminate free-account quotas.

### Local Windows verification

1. Update your working repository only **after PR #22 is merged**: `git pull --ff-only origin main`.
2. In existing private root `.env`, preserve DATABASE_URL, AUTH_SECRET and other credentials. Set `AI_MODE=free`, `OPENROUTER_API_KEY`, `FREE_AI_ORDER=openrouter,gemini,ollama`, `FREE_AI_MAX_CALLS_PER_HOUR=10`; add Gemini key and enable its switch **only if confirmed free billing**; Ollama is optional.
3. Run `npm run test:all`, `npm run test:swagger`, `npm run build`, and `npm run test:e2e` if Chromium and the disposable local test DB are set up. Real DB tests require the dedicated test database, never reset production.
4. **One-shot real inference:** `npm run ai:verify-live`. This script uses invented astrological facts, never a user's birth details, and calls enabled remote models. `PASS` reports the actual returned model. A `FAIL` proves that no accepted external response was obtained, even though offline interpretation still works. The script is not run automatically in GitHub CI and consumes free-tier requests.
5. Restart `npm run dev:full`, generate a report, and inspect the message `data-testid="reading-ai-provenance"`: it reports a real LLM provider/model only after accepted inference. Local fallback explicitly says no external LLM was used; a cached successful response is labeled as such.
6. Test UA/EN, mobile/desktop, two different birth charts and `AI_MODE=local` fallback. Verify model names are never invented and no secrets or birth fields are logged.

**Privacy:** Derived chart findings, not the raw date/time/place, are sent to third-party AI servers. Free cloud providers' data-retention and prompt-use policies must be disclosed before a public release; don't submit client charts without informed consent. No user account details or AI keys are included in telemetry.
